## Вимоги

- Linux-машина - для об'єкта достатньо комп'ютера класу Raspberry Pi;
- Docker з Compose v2 - усе збирається й працює в контейнерах.

## Перший старт

```
cp .env.example .env
make up-all
```

Так запускається платформа (PostgreSQL з TimescaleDB, Redis, RabbitMQ,
оркестратор, API, шлюз повідомлень, UI) разом з ядром EdgeX і
device-service. Увійдіть як `admin` з паролем `ADMIN_DEFAULT_PASSWORD` з
`.env` і одразу змініть його, якщо машина доступна ззовні.

## Налаштування

Усі налаштування - у `.env` (див. `.env.example` - кожне значення з
коментарем): порти, паролі, часовий пояс хоста (`TZ`), ліміти (розміри
завантажень, мови інтерфейсу), ключ шифрування ШІ, команди хоста. Нічого не
зашито в код.

## Обладнання

Вузли на шині CAN потребують CAN-адаптера хоста, підключеного до
device-service; мережеві вузли використовують MQTT-брокер. Доки вузол не підключено, запускайте
його симульованим - Вузли -> його рядок -> симуляція.

## Резервні копії й оновлення

- Сервіс -> База даних -> **Знімки системи**: збережіть конфігурацію
  (пристрої, вузли, процеси, користувачі, групи) як стан, завантажте його,
  застосуйте чи завантажте назад - з попередньою перевіркою сумісності.
- Журнали: завантажте їх або очистіть до дати.
- Оновлення: отримайте нову версію і знову `make up-all` - міграції
  виконуються при старті API; дані зберігаються.
