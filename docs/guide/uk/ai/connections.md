Сервіс -> Конфігурація -> AI: підключення до моделей - OpenAI, Anthropic чи
сумісний з OpenAI локальний сервер (Ollama, LM Studio, vLLM - дані лишаються
на об'єкті); ключ зберігається зашифровано й ніколи не показується; ліміт
відповіді й денний ліміт токенів на підключення; токени на людину на день
(Користувачі).

## MCP - ваші власні агенти

![Доступ MCP - токени, їхні облікові записи й рівні](screen:service-config-mcp)

Ті самі інструменти для будь-якого MCP-клієнта (Claude Code, Claude Desktop,
агент на Raspberry Pi): Streamable HTTP за адресою `/api/mcp` з bearer-токеном.
Сервіс -> Конфігурація -> AI -> Доступ MCP -> **+ Токен**:

- **Назва** - клієнт, наприклад "Claude Code - ноутбук". Один токен на клієнта:
  кожен отримує власний **сервісний обліковий запис** (`mcp-<назва>` у
  Користувачах) - без пароля, він ніколи не входить, працює лише його токен.
- **Ролі його облікового запису** - що він може читати й змінювати і на яких
  об'єктах, так само, як ролі людини (Користувачі -> Ролі). Роль оператора
  енергетики показує йому лише процеси енергетики - інших він не бачить. Роль
  з усіма правами (Адміністратор) не дозволяється ніколи; ролі можна змінити
  пізніше в Користувачах, як у людини.
- **Конфігурація / Керування / Встановити** - що відбувається зі зміною, яку
  дозволяють його ролі: **Авто** - застосовується одразу, автор у журналах - його
  обліковий запис; **Підтвердити** - пропозиція чекає на людину (Журнали ->
  Пропозиції ШІ); **Вимк.** - не пропонується. Встановлення (нові вузли,
  пристрої, процеси) ніколи не буває на Авто. Рівень, права на який ролі не дають
  ніде, вимкнений, хоч би що було вибрано.

Токен показується один раз разом із командою `claude mcp add ...` для
підключення; зберігається лише його хеш. Його рядок: обліковий запис і ролі,
рівні (їх можна змінити тут же), останнє використання, увімкнено, відкликати
(обліковий запис зникає разом із ним). Агент ніколи не змінює нічиїх ролей,
своїх теж, і ніколи не приймає пропозицій. Кожен його виклик - у Журнали ->
Виклики MCP.
